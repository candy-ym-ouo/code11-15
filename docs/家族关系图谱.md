# 家族关系图谱模块

从「人物档案上的称呼」和「物品上的来源角色」两类已有数据推导亲属关系，自动检测矛盾，
支持人工校正、版本留痕与导出。关系数据只有三种基础边，其余关系全部在查询时推导。

## 1. 数据模型

只存三种基础边（`kinship_edges`）：

| 边 | 方向 | 含义 |
| --- | --- | --- |
| `parent` | 有方向，from 是 to 的父母 | 父母 → 子女 |
| `partner` | 对称 | 配偶 |
| `sibling` | 对称 | 兄弟姐妹 |

**祖辈、叔侄、表亲不落地**——沿 `parent` 边走两步就是祖孙，「上-平」两步就是叔姑舅姨。
同一事实只存一份，删掉一条父母边，派生关系立刻同步消失，不会留下自相矛盾的鬼图。

- `Person.gender`：性别。用来区分爷爷/外公、姑姑/舅舅、孙子/孙女。
- `Family.kinshipAnchorPersonId`：锚点人物。人物档案里的「外公」「舅妈」是**相对锚点**的称呼，
  锚点一般是建档人本人；不设锚点时不解读称呼。
- `kinship_versions`：每次写操作前自动存全量快照（人物图谱字段 + 边），回滚即整体对齐。
- `kinship_issues`：矛盾记录，用内容指纹去重，支持忽略，问题消失自动标 resolved。

## 2. 推导

两类线索，置信度不同：

1. **人物称呼**（`relation` 字段，高/中置信度）
   「外公」解析成路径 `父母(女) → 父母(男)`，逐步落地：已有的边跳过，缺的边补成
   `origin=inferred, confirmed=false` 的候选边。路径中间人物未建档时不硬造，只提示缺谁。
2. **物品来源角色**（低置信度，仅建议）
   同一件物品上 A 角色为「继承」、B 为「来源/赠送/原主」时，提示 B 疑似 A 的长辈。
   生活里也可能继承自叔伯，所以**绝不自动坐实**，必须人工确认。

手动录入的边恒为 `origin=manual, confirmed=true`。

## 3. 矛盾检测（`detectIssues`）

| 级别 | 检查 |
| --- | --- |
| error | 自环、parent 代际环（自己是自己的祖先）、性别与一级称呼相反、父母比孩子小（<12 岁）、去世早于出生、父母边正反双向冲突 |
| warning | 父母生育年龄过大（>70 岁）、兄弟姐妹年龄差过大（>25 岁）、多级称呼落不到图上（中间人物缺失）、重复的对称边 |

人物称呼与图谱实际路径不符（档案写「外公」，图里却从「爸爸」连来）报 `title_conflict`。
检测在打开图谱/写操作后自动运行；指纹相同的问题不重复入库，忽略状态跨检测保留。

## 4. 人工校正与版本

- 新增/删除/修改边都要求 `kinship:write`（owner/admin/editor）。
- 推导边可「确认」（confirmed=true），确认只改标记不改关系。
- 每次写操作前在同一事务存快照版本；回滚把当前边集合整体对齐到目标快照，
  回滚本身也留一个新版本，保证可逆。
- 合并人物时亲属边自动迁移：重复/自环边软删，家庭锚点也跟着改挂。

## 5. 导出

- `GET /kinship/export?format=gedcom`：GEDCOM 5.5.1 子集，Gramps/MyHeritage/FamilySearch 可导入。
- `format=dot`：Graphviz，`dot -Tpng family.dot -o family.png` 渲染成图。
- `format=csv`：边总表，Excel/WPS 打开核对。
- 全量 ZIP 导出（物品导出包）在 `kinship/` 目录同时附带以上三种格式。

## 6. API 一览

```
GET    /families/:fid/kinship/graph             图谱（人物+边+相对锚点的称呼）
GET    /families/:fid/kinship/issues[?resolved=1] 矛盾列表（自动检测）
POST   /families/:fid/kinship/issues/:id/ignore  忽略/重新关注
GET    /families/:fid/kinship/inference          推导预览（不落库）
POST   /families/:fid/kinship/inference/apply    采纳推导
POST   /families/:fid/kinship/anchor             设置锚点人物
POST   /families/:fid/kinship/edges              手动补关系
PATCH  /families/:fid/kinship/edges/:id          校正（确认/备注/置信度）
DELETE /families/:fid/kinship/edges/:id          删除关系
GET    /families/:fid/kinship/versions           版本列表
GET    /families/:fid/kinship/versions/:id       版本快照详情
POST   /families/:fid/kinship/versions/:id/revert 回滚
GET    /families/:fid/kinship/export?format=     导出 gedcom/dot/csv
```

纯逻辑（称呼解析、路径推导、矛盾检测、导出格式化）都在 `@heirloom/shared` 的
`src/kinship/` 下，前后端共用且有单测；数据库与事务在 `kinshipService.ts`。

## 7. 刻意不做的事

- 不存「干爹/继父母/堂表细分」等需要法律/语义判断的边类型，避免系统替用户给关系定性。
- 不做三级以上亲属的称呼反推（堂姑表舅的配偶），给泛称「长辈/平辈亲属」而不是硬猜。
- 「继承」线索不自动建边，只做低置信度建议。
- 不引入图库数据库或力导向布局：家谱可读性靠代际分层，一张 SVG 足够。
